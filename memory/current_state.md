> *"제품의 문제 정의부터 실험 설계 및 실험 분석까지 PD가 쓰기 좋은 솔루션."*

이게 진짜 PD 결. TF 미션과 정확히 부합.

### 제안 솔루션 컨셉 — PD 사이클 워크스페이스

```
┌─ ① 문제 정의 ────→ ② 실험 설계 ────→ ③ 실험 분석 ─┐
│                                                  │
└──────────── ④ 다음 사이클 시드로 누적 ──────────┘
```

각 단계가 분절된 도구·문서·사람에 흩어져 있는 현 결을 한 워크스페이스에서 굴리고, 산출물이 다음 단계의 인풋이 되도록 강결합. 사이클이 ④로 누적되어 다음 사이클의 시드가 됨.

### 단계별 페인 + AI 기여 결

| 단계 | 페인 | AI 기여 |
|---|---|---|
| ① 문제 정의 | 지표는 보이는데 *"그래서 뭐?"* 가 안 잡힘. 이해관계자마다 해석 다름 | 지표 데이터 + 과거 케이스 + JTBD/5Why → 문제 1-pager 초안 |
| ② 실험 설계 | 가설 좁히기 어려움. 변수·지표·가드레일 빼먹기 쉬움 | 문제 정의에서 가설 N개 도출 → 각 가설별 실험 설계 초안 |
| ③ 실험 분석 | 유의성·임팩트·코호트별 해석. *"다음 뭐?"* 가 막막 | 결과 + 원래 가설 → 자동 해석 + 다음 PD 액션 N개 |
| ④ 다음 사이클 시드 | 사이클 끝나면 정리 안 되고 묻힘. PD 머릿속에만 남음 | 산출물 자동 인덱싱·검색. 다음 사이클 시작 시 *"비슷한 거 작년에 푼 적 있어요"* |

### PoC 진입점 — 풀 사이클은 6개월 짜리, 작게 자르는 결 필요

후보 3개:

- **🅰️ Analysis Loop** (③ 단독) — *실험 결과 → 해석 → 다음 액션* 한 사이클. **추천**. 2~3주.
  - 시연 깔끔 (실제 더보기탭 실험 데이터로 즉시 데모)
  - 시드 데이터 풍부 (Tiara, 실험 결과 손에 있음)
  - 확장 경로 명확 (Analysis 잘 돌면 → ② Hypothesis Forge → ① 문제 정의 → ④ Cycle Memory 순서로 풀 사이클 완성)
- **🅱️ Hypothesis Forge** (①→②) — *문제 정의 → 가설 + 실험 설계 초안*. 1~2주.
- **🅲️ Cycle Memory** (④) — *과거 사이클 인덱싱·검색*. 시니어 결에 맞지만 단기 임팩트 약함.
